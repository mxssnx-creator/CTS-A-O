# Exit coverage inventory and bounded replay plan

This inventory performs no trade scoring. The actual normalized defaults use 37 focus entries, 24 pinned entries, no disabled indication kinds, and independent/combined 1/5/15/30-minute lanes. Production `baseFocus` expands this to 701 selectors; `allCombos` without a range floor resolves **794 unique Exit pairs from 169 base indication IDs**. They comprise 750 Follow, 29 Revert and 15 Sweep pairs. Lane counts are 16 each for 1m and 1m combined; 144 for 5m, 145 for 5m combined; 155 for 15m, 154 for 15m combined; and 164 for 30m.

Empty focus would instead select every registry combo: **30,062 pairs from 430 base IDs**. That is a different inventory from the configured defaults. The four fixed prior replay symbols remain BTC, ETH, SOL and XRP; no performance-based symbol or pair removal is proposed.

The existing cached 20-symbol public feed has **397 contiguous hours**, from 2026-10-01 08:00 through 2026-10-17 21:00 UTC. This supports a separately frozen **24-hour trading window**, 2026-10-16 21:00 through 2026-10-17 21:00 UTC, preceded by 168 evaluated hours and 72 older indicator-only hours. The complete loaded horizon is 264 hours. Source metadata, original input SHA-256, all default pair identities and per-symbol quality are preserved in the matching inventory JSON. This inventory reuses the earlier verified input hash and cached manifest; it does not make another market-data request or independently audit venue provenance.

The earlier 16-pair, four-symbol, 168h+6h replay took 2.065 seconds and peaked at 158.5 MiB RSS. A simple pair-count/bar-horizon extrapolation is about **110 seconds** for the 794-pair, four-symbol 24h replay, and about 550 seconds for 20 symbols. These are planning estimates, not benchmarks: the default inventory contains denser active signals and combined lanes, and candidate qualification/cache behavior can increase both time and memory. The unchanged per-pair candidate cap allows at most 19,056 candidates for the default inventory, versus 721,488 for every registry combo. A pathological per-bar trade bound exceeds 9 GiB of tape columns for the default four-symbol inventory, so aggregate retention needs a measured memory guard.

The authorized run will fit and build 16-pair chunks, release indicator memos between chunks, retain every holdout-qualified tape, and then execute **one unified default WF**. Default caps, portfolio, ranking and cross-config controls remain unchanged. The only strategy override isolates Exit for attribution by disabling Normal, Trailing, DCA, Axis, Block and Signals; replay window overrides are explicit. Every failed PF/count/DDR outcome and every losing trading hour remains in the output. A 512 MiB heap cap and explicit 768 MiB RSS guard stop the run and preserve failure evidence if the budget is exceeded. A failed partial run cannot replace the unified result with a passing aggregate.
